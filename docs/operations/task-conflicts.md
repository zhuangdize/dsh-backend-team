# 当前对话处理旧任务

2026-09-09：`backend_team_workflow` 增加 `resolve-task`。先查询状态获得 `expectedRevision`，再调用该操作；宿主通过现有逐题确认收集任务选择和处理决定，不接受模型自行提交目标任务或确认结果。

- 接回当前对话：转移会话绑定，保留原需求、阶段和产物；原会话失去该任务的修改入口。
- 搁置并释放占用：等待宿主释放后持久保存 `shelvedAt`，新任务创建不再被该记录拦截；工作区仍有未完成任务时，新需求只持久排队，不创建审批或启动 Agent。没有把 VERIFY 改成 DELIVER，没有删除代码或文档。
- 保持原状、取消、模糊补充意见：不变更任务。

运行中、排队中或控制操作尚未结束时拒绝切换；先暂停并等待停止后重新确认。确认期间任务版本、绑定或搁置状态改变时拒绝过期决定。

暂停入口在存在安全暂停能力时会等待当前切片、最终验证和运行租约释放后才返回；返回前仍不会自动接回、搁置或创建新任务。随后必须重新查询状态并再次确认任务处置，排队或残留活动检查失败时继续拒绝切换。

接回只是恢复管理入口，不自动继续执行或批准方案。接回后先读取已有产物并按实际阶段继续。共享工作区内已存在的代码不会因为搁置而回滚。

任务选择已支持翻页，每页最多 4 项，包含上一页和下一页；不会遗漏第 5 项以后的任务。每次提问使用独立编号，旧回答不能复用到下一次操作。此功能不等同于多任务并行开发或自动隔离工作区。最初的非会话 legacy 记录只供历史查询，不是可转移任务。

页面右上角“团队任务”列出整个工作区任务，可按未完成、已搁置、已完成筛选并搜索。查看详情、范围与文档不会接回或启动任务。页头同时显示当前会话实际关联的任务。接回、搁置在右侧底部确认，后台签发会话绑定且 5 分钟有效的一次性确认编号，并重新核对任务版本和归属。输入补充意见时只保存意见，不切换任务。管理操作与意见持久化到任务记录；这些记录不替代文档审批凭据。

验证：3 个相关测试文件 24 项通过，包括过期决定、旧会话失效、搁置后创建新任务、重启恢复及明确确认/取消。构建、类型检查和相关 ESLint 通过。本地 web profile 已升级重启，Chrome 页面重新加载；本轮未代用户操作真实任务，也未声称真实任务确认全链路已验收。

## 开发或验收中补充需求（2026-09-09）

在原对话说明要调整什么，Agent 调用 refine 后会逐步询问是修改当前任务还是独立新任务。选择修改时，先等开发及最终验证停止，再保存变更请求和旧文档/审批/运行记录，撤回需求与设计审批，归档旧计划检查点。已有业务代码保留，新需求及设计必须分别明确确认后才能恢复开发。

生成阶段失败或重启后，可在对话要求继续；SPECIFY 的 continue 调用已保存变更恢复，不会恢复旧开发检查点。如果停止期间任务版本变化，本次变更会拒绝执行，需要刷新状态后重新确认。独立新需求在工作区被占用时持久排队；旧任务经聊天明确搁置并释放后，同一会话最早的排队任务自动衔接，排队期间不会继承旧审批或运行状态。旧基线范围不匹配属于独立问题，本入口不会伪造或扩大历史基线。

验证：6 个测试文件 49 项通过，工作区构建、类型检查、相关 ESLint 和 diff 检查通过；本地 bundle 已安装重启。真实业务的需求变更和审批未代用户执行，因此完整模型/审批/交付验收仍待完成。

### 控制版本栅栏（2026-09-12）

真实宿主曾出现持久化状态 revision 已前进、事件投影仍落后时的误报 `STALE_VIEW`：状态查询能读到新版本，但继续操作仍拿缓存投影做版本比较。生产控制面现在从同一 durable state store 读取权威 revision，再执行 `expectedRevision` 栅栏；关闭宿主时会先拒绝新调用并等待已进入的控制调用排空。`packages/web/test/control-service.test.ts` 覆盖投影落后、关闭排空和跨工作区场景，避免后续把状态查询成功误判为控制通道可用。
