# 团队工作区设计与实现约束

## 设计依据

用户确认稿：[审批](references/review.png)、[逐题问题](references/questions.png)、[修改回执](references/feedback.png)、[执行进度](references/progress.png)。原图 1586×992（部分图宽略有不同），按同一 CSS 视口对照。图片内示例业务文案、版本号不作为真实任务事实。

2026-09-09 用户明确选择“按这个方案实施”的任务中心原型：`docs/design/task-center-prototype/`，本机预览 3091。右侧任务列表→详情→资源预览；接回/搁置在右侧底部确认，支持可选意见；聊天页头标明实际关联任务。原型使用现有 shadcn 本地组件与主题，不连接业务服务。正式宿主复用公开页头 actions 插槽展示绑定信息，保留原 DSH 会话、模式和输入框。

## 本次失误与改正

上一版跳过了原稿尺寸和组件清单的提取，把局部 Button/Textarea 接入称作整体还原；没有在 DSH 的真实 CSS 层叠和三栏布局中完成视觉比较；测试只覆盖交互逻辑，却被用于整体完成结论。空状态也未纳入验收。

纠正：先保存原稿并列出尺寸与状态，再实现统一组件和宿主适配，最后将原稿与真实宿主截图放在一起复验。功能检查和视觉检查分别汇报。

## 视觉规范

- 白色背景、深色正文、蓝色文件图标与进行中状态；绿色已确认、琥珀色待确认。颜色由局部主题统一管理，支持宿主深色主题。
- 字体继承系统中文字体；正文 14px/1.7，标题 18–20px/1.4，辅助信息 12–13px。文档单独控制排版，避免宿主 Markdown 标题过大。
- 间距以 4px 为基数：工具栏 16/24px，阅读内容 24px，区段 24px，控件间距 8px。
- 主按钮深色，次按钮细边框无厚阴影，工具按钮 ghost；圆角 6–8px。
- 宽屏保持左侧会话、中心聊天、右侧审阅并列；右侧约 36% 且不大于 600px；窄屏优先保留聊天可用空间，不覆盖输入框。可调整面板宽度。
- 右侧：标题与图标关闭；返回所有资源；文件标题/真实状态；分段页签；可滚动文档；底部固定审批。
- 无资源时显示居中图标、标题及简短说明，可收起返回对话；不显示空资源列表和无用页签。
- 变化只能来自真实版本差异，缺少基线明确提示；不伪造原稿中的 v2 或更新摘要。

## 组件与权限

Button/Textarea/Badge 使用 shadcn/ui 本地组件模式；Tabs 使用 Radix 支持的 shadcn 模式；图标采用与原稿线性图标匹配的 Lucide。样式限定在 .bt-ui，宿主布局兼容逻辑单独管理并在卸载后恢复。保持宿主 React 单例。

模型提供的 A2UI 仍受现有白名单限制。所有审批、任务、版本、权限检查保持在 DSH；界面展示回执不等同于后端已批准。

## 验收

使用 Codex Chrome 插件。覆盖真实宿主空状态、文档、问答、待审阅、反馈回执、执行状态；真实业务不可为测试代批。使用隔离任务/载体时明确标识。检查正常、加载、失败、禁用、关闭重开、键盘操作及窗口变化。证据和未完成项记录在根目录 design-qa.md。

实际宿主发现的根因：首轮 `.bt-ui *` 仅重置子元素，漏掉 `.bt-ui` 自身；聊天卡片根节点按 content-box 计算，100% 宽度再加左右 padding，导致边缘被截断。另有无效 font 简写被 CSS 优化器合并后回退到浏览器字号。已改为包含根节点的局部 box-sizing 与有效字体长属性，使用浏览器最终样式复验。
