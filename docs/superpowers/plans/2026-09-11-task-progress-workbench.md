1. **TaskHeader**：任务标题；“团队任务”类型、五阶段名称、独立状态 Badge、最后进展时间；查看技术详情 / 查看任务资源 / 暂停任务。页头关联标识复用同一映射，但不重写 DSH 会话标题。
2. **CurrentProgress**：正在做、最近完成、当前问题、下一步。问题需要用户处理时带“查看并处理”入口；不在此创建第二组批准按钮。
3. **StageProgress**：五阶段有序列表。当前节点设置 `aria-current=step`；不显示虚假的百分比或耗时预估。
4. **RecentActivity**：事件归约后的精选活动。最近 3 条按时间顺序展示，查看更多可放到技术详情；“下一步”只出现在计划行，不能伪装成已经发生的活动。
5. **TechnicalDetails**：页内非模态展开，与两处“查看技术详情”共享一个开合状态；保留诊断、执行记录、验收范围/报告位置及已有人工接管能力。提供“完整执行轨迹请查看顶部「轨迹」”说明。默认不渲染 Think/Bash/raw JSON；已有原生对话与轨迹内容不删除、不用全局 CSS 隐藏。

主题：所有首页规则限定 `.bt-ui .bt-progress-home`（根节点本身也要正确匹配）。局部复用蓝/绿/灰 tokens；受阻补红色 tone，等待处理用琥珀色。首页“查看技术详情”采用原稿蓝色主按钮，仅限本组件，避免把已有审批主按钮一并改色。按钮与 Badge 复用 shadcn 本地组件；进度条使用语义化列表，无新增 stepper 依赖。

原稿中“进行中”徽标为绿色，而既有规范偏蓝：首页任务级“进行中”采用原稿绿色，当前阶段和正在做仍蓝色；已完成使用勾图标，进行中使用活动图标，不能只靠颜色区分。状态文案统一，色彩在新首页与紧凑卡同步。

## 4. 状态映射：阶段和运行状态分开

业务 Badge 只使用 **进行中、等待系统验证、等待你处理、已受阻、已完成、已暂停**。加载、无任务、连接失败是页面状态，不硬塞进六种业务状态。

五阶段映射：DISCOVER/SPECIFY/AWAIT_REQUIREMENTS_APPROVAL → 需求分析；DESIGN/AWAIT_DESIGN_APPROVAL/PLAN → 方案设计；BUILD → 功能开发；VERIFY → 测试验收；DELIVER → 交付。PLAN 是设计落成后的执行拆分，不代表代码正在运行。阶段名称与 Badge 各占独立位置。

优先采用认证会话当前任务的快照，决策顺序如下。当前且未解除的阻塞必须保留在“当前问题”，不能被最近一次成功覆盖。

| 条件（按优先级） | Badge / 行为 |
| --- | --- |
| 首次加载、无 taskId 或 unassigned、无法读取有效状态 | 使用第 7 节页面状态；旧页面快照与连接失败同时出现时标注“状态未更新”，禁用写操作 |
| 只读不兼容，或失败/阻塞与当前审批无因果关系且仍阻断任务 | 已受阻；显示可理解原因和技术详情入口；不以“有审批”掩盖另一个运行错误 |
| 当前版本的有效待审批，或来自当前会话宿主的待答问题/操作确认 | 等待你处理；按钮只打开现有资源审阅或定位现有问题；显示具体事项而非“继续” |
| `developmentRun.status=failed/blocked` 或当前 `risk.level=blocked`，且没有明确匹配的可处理等待项 | 已受阻；保留技术原因供展开。不能从英文错误猜测“需要你批准” |
| `paused` | 已暂停；提示进度已保存（仅在宿主确实提供保存事实时），恢复沿用原动作 |
| `pausing` | 仍为进行中；“正在结束当前步骤并暂停”，暂停按钮禁用，宿主返回 paused 后再变更 Badge |
| 当前运行标识为最终验证且正在运行 | 等待系统验证；“系统正在执行交付前检查，你暂时无需操作” |
| 其他可信实时运行：developmentRun running 或当前 scheduler 活跃 | 进行中；用阶段级模板或已提供的安全摘要描述工作 |
| DELIVER 且当前 delivery ready、需求证据非空且全部 passed、没有未解决事项/失败/阻塞/活跃运行/当前待确认 | 已完成；只说明报告限定的验收范围；提供交付资源 |
| passed 但没有可信最终交付证据 | 不当作任务完成；如确有系统验证运行则等待系统验证，否则已受阻，细文案“本轮执行已结束，尚未确认后续检查”，可查看详情 |
| idle / 无执行信息 / 等待阶段却无有效审批 | 有服务器支持的恢复动作则等待你处理（“任务尚未运行，可恢复”/“确认入口需要重新发起”）；无动作且无运行证据则已受阻，明确状态缺失 |

补充规则：

- 历史 `experts` 中的 running 不能凌驾于当前 developmentRun/scheduler 的 idle、failed 等状态。历史审批只在资源记录中表达其来源和文档版本。
- 阶段已推进表示流程位置已经过该阶段，不自动证明批准。需求/设计节点需要可信对应审批来源才用实心绿勾；旧记录来源未知时显示中性节点及“历史记录待核实”，资源可追溯。
- 当前 phase 和执行状态矛盾时展示阻塞说明，不前端修改 phase；需求变更回到早期阶段时清除旧阶段的完成外观，保留历史记录入口。
- 验证 `total=0` 不显示“全部通过”；需求条目数、工具检查数与测试用例数使用各自名称。原稿 53/53 只有结构化测试证据存在时才能显示。

## 5. 展示数据与流转

沿用：任务域状态/持久事件 + 实时运行/审批 feed → `BackendTeamViewProjector` → 会话路由补齐当前任务及 scheduler → `/control/state?sessionId=…` → Zod 校验与 control client → 首页纯展示模型 → 首页/紧凑卡/关联标签。

新增字段是以下**计划**，不是已经存在的 API：

- `BackendTeamViewState.activity?`：最多 20 个精选事件，字段 `id/sequence/occurredAt/kind/label`；kind 只含 stage/run/approval；不放 prompt、工具参数、完整 Markdown 或凭据。默认首页取最近 3 条。
- `BackendTeamViewState.lastProgressAt?`：最近一个可信业务事件发生时间。从事件或 core run 时间恢复；没有证据显示“进展时间暂不可用”。轮询成功时间可单独表示连接新鲜度，不能替代进展时间。
- `developmentRun.step?`：`implementation | final-verification`，只读观测标识；控制器进入 verifyFinal 前后设置/清理。同步相关生产端接口及投影 schema，保持运行状态机、调用时机、权限和数据库行为不变。
- 当前问题补充来自宿主既有 interactions / review store：只映射是否待处理、标题和定位方式；不复制 `respond` 的授权、校验或持久化逻辑。首次接线用生产 `id/header/payload` 验证。无法取得等待项时显示“确认入口暂不可用”，不能显示“无需处理”。

活动归约规则：按 sequence 去重/排序，同 run 后续结果更新同一项而不重复堆满；保留原发生/完成时间。阶段用本地中文模板；运行记录采用“本轮执行已结束/执行受阻”等可信模板。已有任意长度 taskSummary 默认放技术详情，不直接截断英文思考文本充当精选摘要；未来没有结构化切片名时，“正在编写并检查功能”比臆造“补充员工编号测试”准确。审批事件只描述“记录了需求确认”等事实，来源未知时显式注明。

下一步由阶段与当前等待项模板生成：待确认→确认后进入下一阶段；开发→完成后检查；验证→通过后交付。按钮只对应现有支持动作；没有执行证据时不说系统将自动恢复。

刷新与兼容：

1. 保留现有认证路由和轮询节奏，不新造事件服务。首页使用 control client；紧凑卡和关联标签至少复用同一纯状态映射，避免三套互相矛盾的文案。
2. 会话或 taskId 改变时立即清空上一任务显示/技术详情状态，取消或忽略旧请求；新任务低 revision 合法，旧任务迟到响应不能覆盖新任务。
3. 新字段 optional，旧持久事件和旧快照仍能读取。event-projector facade 只导出实现，活动转换保持在一处。
4. 活动/lastProgressAt 是事件投影字段，只随被接受的新事件变化；step 位于已允许实时变化的 developmentRun 内。不要把当前时间写入状态造成同版本 INVALID_STATE。如果 scheduler 等既有实时字段触发同版本错误，只为实际动态字段设置明确比较策略并测试，不移除 task/workspace/revision 检查。
5. 旧客户端 strict schema 不能自动接受新字段，因此客户端与服务端按同一 Bundle 配套交付；不宣称混装兼容。新客户端接旧快照必须显示降级提示而不报完成。

## 6. 操作与资源

- **查看任务资源**：调用 `installTaskResources().open()`。保留并列布局、关闭/重开和读取位置；不自动批准，不新开空白管理页。
- **查看并处理**：需求/设计转现有右侧审阅；逐题问题回现有聊天确认区。迁移等由既有宿主控件负责；先核对可定位入口，无法定位时明确提示并保留原生入口，不能用无效按钮交付。
- **暂停任务**：仅现有模型允许 pause-run 时提供，携带 workspaceId/taskId/expectedRevision；请求中禁用重复触发。accepted 只代表提交，直到状态返回 paused 才显示已暂停。恢复复用原有受控入口。
- **技术详情**：两处按钮控制同一个非模态区域，展开后滚动到区域标题并管理焦点；关闭回触发按钮。状态更新不能折叠阅读内容或让滚动跳顶。完整轨迹通过宿主原生页签查看；不依赖私有 DOM class、模拟点击或新建 chat store。
- 首页不显示数据库启停/安装按钮作为正常任务步骤；已有手动排查能力留技术详情。数据库准备仍由 Agent 按原权限执行。

## 7. 页面状态与可访问性

| 状态 | 显示与操作 |
| --- | --- |
| 首次加载 | 标题、卡片与活动骨架；aria-busy；不闪现另一任务；无写操作 |
| 未选会话 / 尚无关联任务 | 区分“请选择项目会话”和“在对话中描述需求”；不显示五个已开始节点或完成徽标 |
| 活动为空 / 字段缺失 | 保留当前进展卡，活动区写“暂无可展示的活动”；不伪造最近完成或时间 |
| 初次连接失败 / 401 | “任务状态暂不可用”或“当前项目会话未连接”，提供重新加载；普通聊天保持可用 |
| 后台刷新失败 | 保留最近可信内容，显著标明状态未更新及最近成功读取时间；禁用写操作，允许资源只读查看/重试 |
| 提交动作失败 / 过期版本 | 展示“操作未完成，状态已变化，请刷新后重试”；保留上下文，不把提交回执当业务完成 |
| 等待处理 / 受阻 | 原因及唯一可执行入口；长错误在详情中，摘要行可换行，不隐藏关键待办 |
| 禁用 / 正在暂停 | 可见原因、原生 disabled；防重入；键盘操作与鼠标一致 |
| 深色 / 窄屏 | 复用宿主主题；以内容容器宽度决定横/纵阶段，右侧资源打开后也适用；不依赖整个 window 宽度判断 |

宽屏横向五阶段；内容宽度不足约 760px 改为纵向，标题/按钮换行；900px 以下沿用既有资源上下分区策略。检查 1024×768、820×900、390×844，允许自然滚动，不把所有内容压入一屏。保留可见焦点、图标说明、状态文字；`aria-live=polite` 只播报状态变化，不能每次轮询重播整页。减少动态效果设置下无脉冲动画。

## 9. 验证与风险

实施时按任务清单运行对应测试，再执行受影响工作区 typecheck、Bundle 构建与本地修改文件 lint。Web 独立 tsc 不会证明最终 CSS 与 Bundle 集成正确，需检查 Bundle 的 build-team-theme/build-client-entry 产物。既有测试用手写 React hook 顺序桩，重组组件时应保留行为断言；新增首页使用语义渲染断言，避免把 hook 下标当 UI 合约。

必须覆盖：六状态及其冲突优先级；BUILD idle、PLAN 无活动、pausing、passed 无 delivery、DELIVER 验收缺失、迁移待确认、历史审批来源未知；事件重复/乱序/重放/字段缺失；同版本动态变化；任务切换迟到请求；断线/401/只读/过期按钮；展开详情和资源往返；暂停重复点击与服务端失败。

视觉验收只使用 **Codex Chrome 插件 + 实际 DSH 宿主**。实施完成且获准进入运行验收后，先保存真实初始截图，再用宿主中的隔离 UI 载体覆盖原稿同状态和错误状态；载体清楚标明样例，不批准真实任务。主对照 CSS 视口 1672×941，同时记录 DPR、缩放、DSH/Bundle 版本、主题和任务状态。逐区比对标题、卡片、四行、节点线、最近活动、按钮、资源打开后的比例；同尺寸并排截图修正后再拍。实际侧栏差异记录，不用重绘侧栏掩盖布局问题。

证据建议保存 `.backend-team/artifacts/task-progress-home/`：`baseline-*`、`host-*`、`compare-*` 以及状态/视口清单。记录到 design-qa.md：截图路径、差异、修改、复验结果、仍未验证项。单元测试不勾视觉验收；Chrome 不可用则保留待验收状态，不切换其他浏览器。本规划轮不启动 DSH、不执行迁移/审批、不跑构建或业务流程。

主要风险及控制：

- **样式仍偏离原稿**：首页单独作用域，不复用 composer 的 780px/max-height；去除 overlay 旧样式冲突，以最终计算样式和截图验收。
- **运行/审批数据不足**：明确只读新增字段及旧版降级；不解析 message 猜运行子阶段，不给缺证据节点画完成勾。
- **同版本刷新报错**：控制客户端保留一致性边界，只调整真实动态字段比较；活动以事件顺序更新。
- **与人员管理并行修改冲突**：开始实施前确认工作树差异；production/controller 等交叉文件只做小范围只读观测改动，不能回滚别人的修复。
- **旧功能被重排丢失**：移走的每一项能力在技术详情或资源中有对应入口；保留授权、查看版本与可选意见回归，不能为新首页另造批准路径。
