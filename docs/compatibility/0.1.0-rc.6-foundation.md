## Capability and safety boundary

The real profile proved Bundle installation, exactly-once root composition,
Cordis activation, official tool lookup, and official tool execution. The
Bundle registered only `backend_team_status`; it registered no global guard,
write-capable tool, dependency installer, migration runner, database process,
or Agent-spawn tool. The mock integration also confirms untrusted caller-provided provenance and unknown inputs expose only this diagnostic tool and report no workspace writes.

The official rc.6 Context does not provide a trusted runtime-version field to
the Bundle. Therefore the production report remains `version: "unknown"`,
`mode: "read-only"`, and does not grant writes even though this exact CLI
profile is now verified in the compatibility matrix. This evidence promotes
the host compatibility entry only; it does not enable business-code changes.

Known upstream risk: the pinned rc.6 dependency wave reports one npm audit
high finding. It was recorded without running `audit fix` or changing the
pinned tree.
