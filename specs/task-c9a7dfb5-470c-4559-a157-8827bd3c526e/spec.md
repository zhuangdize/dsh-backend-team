# Feature Specification: Greeting Demo 接口（greeting-demo）

**Created**: 2026-09-08
**Status**: Draft，等待用户确认后进入设计/开发

为演示目的新增一个只读的 HTTP 接口：`GET /greeting?name=小明`，返回 JSON `{"message":"你好，小明"}`。所有新增文件仅限 `src/greeting-demo/` 与 `test/greeting-demo/`，不改动任何已有文件与已有健康检查接口。

## Actors

- **演示调用方**：任意匿名 HTTP 客户端，通过 `GET /greeting` 获取问候语。
- **维护者**：在本仓库内以演示功能视角使用这些文件与测试的开发者。
- **既有系统**：仓库中已存在的健康检查接口与服务入口，本次仅要求「不被改变」。

## Flows

1. 调用方发起 `GET /greeting?name=<值>`。
2. 服务端读取 `name` 查询参数，去除首尾空白字符。
3. 若结果非空：返回成功响应，消息为 `你好，<去空白后的值>`。
4. 若无 `name` 参数、参数值为空、或去空白后为空：消息为 `你好，访客`。
5. 响应体为单一字段 JSON：`{"message":"..."}`。
6. 既有健康检查接口行为与响应保持完全不变。

## Rules

- **FR-001（接口）**：仅对 `/greeting` 提供 `GET` 行为；本需求不改变其它路径的行为。
- **FR-002（默认值）**：缺失 `name` 时按「访客」处理。
- **FR-003（trim）**：`name` 去除首尾空白后为空字符串时同样按「访客」处理；中间空白保留原样。
- **FR-004（编码）**：`name` 按 URL 解码并以 UTF-8 处理，中文（如「小明」）原样出现在消息中。
- **FR-005（响应格式）**：成功响应体是有效 JSON，且只含 `message` 字段。
- **FR-006（重复参数）**：同名参数出现多次时取第一个值（合理默认，见 clarification.md Q1）。
- **FR-007（无副作用）**：该接口不读写状态、不持久化数据。

## Permissions

- 无需登录、无需授权：纯演示、只读、匿名可访问。
- 调用方无权访问或修改任何数据（接口本身不提供写操作）。
- 维护者权限范围受交付约束限制：只允许新增两个目录下的文件。

## Data and Privacy

- 本功能**不引入任何数据存储**（无数据库、无文件写入、无缓存）。
- `name` 为一次性输入，仅在内存中参与消息拼装；默认**不记录**原始 `name` 到日志，避免把用户输入写入持久载体。
- 不收集、不关联个人身份信息；消息模板为固定中文文案。

## Integrations

- **既有健康检查接口**：不修改、不重定向、不改变其响应与路由（用户约束 4）。
- **运行时**：仅使用 Node.js 自带能力（原生 `http`、内置测试 runner 等），**不新增第三方依赖**（用户约束 5）。
- **数据库 / 外部服务 / 网络调用**：不适用，本功能不需要任何外部集成。
- 因不允许修改已有文件，演示接口的服务方式作为设计阶段决策记录（见 clarification.md Q2）。

## Non-Functional Requirements

- **可验证性**：每条 Acceptance Criteria 都能通过内置测试 runner 或一次 HTTP 请求直接观察。
- **兼容性**：新增内容不得影响既有接口的既有行为与既有测试结论。
- **纯净性**：安装步骤无需网络与新依赖包。
- **不设定性能目标**：本需求未提出吞吐或延迟要求，故不臆造指标。

## Non-Goals

- 不做生产级加固：限流、鉴权、审计、监控、错误重试均不在范围内。
- 不做国际化框架或多语言模板；仅固定中文问候语。
- 不新增 `/greeting` 之外的业务接口，不重构现有路由或工程配置。
- 不引入前端页面、CLI 工具或数据库迁移。

## Acceptance Criteria

1. **AC-001**: `GET /greeting?name=小明` 返回状态 200，响应体 JSON 为 `{"message":"你好，小明"}`。
2. **AC-002**: `GET /greeting`（无 `name` 参数）返回 `{"message":"你好，访客"}`。
3. **AC-003**: `GET /greeting?name=`（空值）返回 `{"message":"你好，访客"}`。
4. **AC-004**: `GET /greeting?name=%20%20`（仅空白字符）返回 `{"message":"你好，访客"}`。
5. **AC-005**: `GET /greeting?name=%20小明%20`（首尾空白）返回 `{"message":"你好，小明"}`，中间空白保留。
6. **AC-006**: 成功响应的 `Content-Type` 为 `application/json`，且响应体可被解析为只含 `message` 字段的 JSON。
7. **AC-007**: `GET /greeting?name=张三&name=李四` 返回 `{"message":"你好，张三"}`（取第一个值）。
8. **AC-008**: 本次交付后，既有健康检查接口的路径、状态码与响应体与交付前完全一致。
9. **AC-009**: 仓库中新增文件的路径全部位于 `src/greeting-demo/` 或 `test/greeting-demo/` 之下，且没有任何已有文件被修改或删除。
10. **AC-010**: 上述行为均由 Node.js 内置测试 runner 的自动化用例覆盖，运行这些用例不需要安装任何第三方依赖。
