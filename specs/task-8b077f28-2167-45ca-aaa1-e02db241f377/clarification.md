# 人员管理功能 需求澄清

原始需求为"开发一个人员管理功能"。本轮已就 4 项关键业务决策向用户确认，结论如下，并已同步写入 `spec.md`。

## 已确认结论（本轮用户答复）
1. **Q1 生命周期范围 → 完整入转调离**：建档、调岗、在职变更、停用均支持生效日期与任职区间校验，并保留字段级历史。对应 spec F1–F5、R2/R3、AC-003–AC-006。
2. **Q2 使用者与权限 → 仅 HR 管理员**：本迭代只授予 HR/人事管理员全量读写；不向部门主管或员工本人开放查看或变更。对应 spec Permissions、Non-Goals、AC-008。
3. **Q3 权威来源 → 本系统自维护**：人员数据由 HR 在本功能内录入与维护，不对接外部人事或通讯录系统，无入站/出站同步。对应 spec Integrations。
4. **Q4 属性范围 → 基础与雇佣信息**：纳入工号、姓名、联系方式、雇佣类型与起止、组织岗位与汇报关系、在职状态；证件号、薪酬、银行账户等敏感字段本迭代不纳入。对应 spec Data and Privacy、Non-Goals、AC-009。

## 团队已采用的假设（无需用户答复即可推进）
- 领域定位：组织内部人员（员工）主档案管理，非客户/访客名册。
- 生命周期基线：草稿 / 在职 / 停用；被业务引用的档案不允许物理删除。
- 历史与审计：字段级前后值、操作人、时间与生效期间为默认交付内容。
- 查询形态：默认在册视图 + 条件筛选 + 分页。
- 技术边界：沿用仓库既有 Node/TypeScript 与 PostgreSQL 技术栈及模块边界，不新建重复的人员存储。
- 验证口径：性能与容量指标未获授权前不写入需求；宿主计划内的自动化测试由宿主在后续阶段执行并记录。

## 待确认问题（Pending）
无。Q1–Q4 已全部确认，本迭代不存在阻碍实施的业务选择。若后续要扩展部门主管/员工权限、纳入敏感字段或引入外部同步，需重新走澄清流程。
