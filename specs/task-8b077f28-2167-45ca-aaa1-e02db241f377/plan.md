# 人员管理功能 实施计划

需求：`spec.md`（F1–F5、R1–R7、AC-001–AC-011）。设计：`architecture.md`。契约：`contracts/openapi.yaml`。
本计划阶段不写业务代码（`businessCodeWrite=false`）；下列落地文件均在宿主允许的 `src/`、`test/`、`migrations/` 内（相对于实施前确认的宿主包目录）。

## 前置确认（阻塞实施开始，不阻塞本计划）
1. 宿主包与服务边界：`personnel` 模块落在哪个既有包、路由前缀挂载点。
2. HR 管理员身份来源：复用宿主会话/角色的哪一种，以及未认证与无权限的区分方式。
3. 「被业务引用」的判定依据：引用关系来自哪个既有模块（用于 AC-006/AC-007）。

## 数据模型（落 `src` 领域与迁移层）
- `person`：主档案。`employee_no`（唯一、停用后不复用，R1）、姓名、联系方式、雇佣类型与起止日期（Q4 范围，无证件/薪酬/账户）、状态（`draft|active|inactive`）、停用原因、`created_at/updated_at`。同一自然人仅一条主档案（R1）。
- `assignment`：任职区间。人员 id、部门标识与名称快照、岗位标识与名称快照、汇报上级人员 id、`effective_from`/`effective_to`；同人区间不重叠（R3）；上级须在职且无环（R4）。
- `change_record`：字段级历史。动作、字段名、前值、后值、操作人、时间、生效期间（F5、AC-010）。
- 约束：状态仅 草稿→在职→停用（R2）；无物理级联删除；彻底删除仅在无引用且获授权时（Data and Privacy）。
迁移拆分：M1 `person` + 唯一索引；M2 `assignment` + 区间与外键约束；M3 `change_record` 追加写与权限（仅 INSERT）。

## 实施里程碑
- **M0 边界确认**：与用户确认上述 3 项，固定包路径与迁移目录。
- **M1 契约与骨架**：按 `openapi.yaml` 生成 DTO 与校验层；未接入规则时返回 501 语义不落地（不提交半成品接口）。
- **M2 建档与在册列表**：F1/F2 + 分页筛选；打通 AC-001–AC-003。
- **M3 在职变更与调岗**：F3 + 区间不重叠、汇报无环；打通 AC-004、AC-005、R3 撤销。
- **M4 停用与历史**：F4/F5 + 只读查询接口给下游；打通 AC-006、AC-010、受限删除 AC-007。
- **M5 授权收口**：服务端角色门禁与 403/404 不可区分策略；打通 AC-008、AC-009 字段清单核查。
- **M6 回归**：既有模块构建与既有自动化测试全绿（AC-011）。

## 验证设计（每个 AC 至少一条用例）
- 单测（domain 层，纯函数规则）：R1 唯一与不复用、R2 状态机、R3 区间重叠、R4 自引用与环、R6 校验消息为中文且指明缺失字段。对应 AC-001、AC-002、AC-005。
- 集成（test 容器或宿主既有 PostgreSQL fixture）：建档后可在默认在册列表检索（AC-003）；调岗后详情新值 + 历史前后值（AC-004）；停用后不在默认列表且不可指派、历史与业务记录仍可见（AC-006）；引用删除返回 409（AC-007）；历史含操作人/时间/前后值（AC-010）。
- 契约与安全：`openapi.yaml` 一致性校验；HR 与非 HR 两类身份访问同类资源，断言 403/404 与响应体不泄露存在性（AC-008）；断言请求/响应 schema 无证件号、薪酬、银行账户字段（AC-009）。
- 回归：既有测试套件与构建（AC-011）。
