# Test Plan

## Requirement ID

Map each test to one or more requirement or acceptance-criterion identifiers.

## Evidence Type

Choose unit, integration, contract, migration, security, performance, or end-to-end evidence and explain why it is sufficient.

## Command or Scenario

Give the exact command or a reproducible scenario, including fixtures, request payloads, authentication context, and required database state.

## Expected Result

State the observable response, persisted changes, emitted events, logs, and failure behavior that proves the requirement.

## Status

Use `Planned`, `In Progress`, `Passed`, or `Blocked`, and link the evidence or explain the blocker.
